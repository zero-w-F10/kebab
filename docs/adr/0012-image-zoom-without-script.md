# 图片放大走原生 popover，产物里没有一行脚本

状态：已接受（2026-09-21）

doc 页正文栏有宽度上限（[ADR-0014](0014-doc-column-width.md)：1600px，去掉边距后 1504px），比它宽的截图进去就被压小 —— 在 1707 的一屏上正文栏 1347px，1920 宽的整屏图只剩七成 —— 评审时要看清字还得点开看。因此正文里的图片点开可以看大图：原尺寸居中显示，点图周围的空白处或按 Esc 退出。

放大天然要脚本，而产物是「零运行时 JS 依赖」——导航树、代码着色、条目编号全在构建期烘好（[ADR-0001](0001-file-protocol-compatible-output.md)），这一条没有为放大破例，改用 HTML 的 `popover`：图片包一层带 `popovertarget` 的按钮（`popovertarget` 只认 button 与 input），旁边放一份铺满视口的放大层。打开、按 Esc 退出都是 `popover=auto` 的原生行为；放大层里再压一颗占满视口的透明按钮接住「点空白处退出」——放大层既然铺满视口，层外就没有地方可点，原生 light dismiss 指望不上。那颗按钮同时把「再点一次图」也接住：图自己 `pointer-events: none`，点图落到它身上。**已经在链接里的图不包按钮**（`[![说明](图)](地址)`），按钮套进 `a` 里一次点击会同时触发放大与跳转。

放大只卡宽度（92vw），不卡高度：整页截图与手机长截图动辄一两千像素高，按高度缩进视口反而比正文里看得更小，字全糊。这种图给的是原尺寸宽度加可滚的放大层（`overflow: auto`，`align-items: safe center` 让「不溢出就居中、溢出就顶头」两件事各归各位），接点击的透明按钮用 `fixed` 而不是 `absolute` —— 否则放大层一滚，按钮跟着滚走，滚过一屏就再也没有接点击的东西。

## Consequences

- 产物里仍然没有一行脚本，`file://` 双击照旧，放大也不例外
- 每张可放大的图在 HTML 里多一份 `<img>`（同一个 src，浏览器只取一次）加两颗按钮；id 形如 `<page-id>-zoom-1`，与锚点同一套写法，跨页不会撞车
- 放大只到原尺寸，小图不拉大（拉大只是糊）：被正文栏压过的截图才看得出差别
- 放大层靠 `:popover-open` 与 `::backdrop`。认不出 `:popover-open` 的浏览器里整套隐藏（`@supports not selector(:popover-open)`），代价是那些浏览器没有放大，正文本身照旧 —— 比让那份副本摊在正文里强

## Considered Options

- **内联一段脚本做 lightbox** —— 最直白的做法，也正是本项目的硬约束要拦的东西：多一行脚本，就是把「双击即看」换成「赌浏览器肯跑脚本」
- **放大层用 `:target` 替代 popover** —— 同样不要脚本，但 Esc 退不掉（只能再点一次链接或按后退清 fragment），而 Esc 退出是这次点名要的行为
- **`<dialog>` + `showModal()`** —— 语义与行为都最贴，但打开只有脚本一条路
- **只靠 CSS 把图 `transform: scale()`** —— 撑不出真正的原尺寸，超出正文栏还要 `overflow` 兜，「点空白处退出」也没有落点
- **按 92vw × 92vh 把整张图塞进视口** —— 常规截图看着更整齐，但整页与手机长截图点开会比正文里还小，等于把「放大」做成了「缩小」

## 范围

只作用于 doc 页正文里的图。proto 页是 iframe，原型目录进库后不再改写（[ADR-0007](0007-prototype-import-check.md)），里面的图不在此列。
