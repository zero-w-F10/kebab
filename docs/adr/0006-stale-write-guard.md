# 陈旧写入防护

状态：已接受（2026-09-19）

浏览器编辑器把状态读进内存后，Agent 可能在后台直接改了 `site.json` 或某个 `.md`；此时保存会用内存里的旧状态无声覆盖掉 Agent 的改动，属于最难发现的一类数据丢失。因此编辑器监听 `site.json`、`pages/`、`assets/` 的变化，检测到外部改动即把内存状态标记为 stale 并提示重载，stale 状态下保存被拦截——判定依据是修改时间加内容哈希，不只看时间戳。

## Consequences

- 浏览器编辑和 Agent 直接写文件可以安全共存，这是本项目要成立的前提
- 需要引入文件监听与版本校验
- 用户偶尔会遇到「请先重载」的打断，属于可接受的摩擦

## Considered Options

- **自动保存**——冲突窗口更大，且没有提示的时机
- **last-write-wins**——直接丢数据
- **只用文件锁**——锁无法约束 Agent，它不会遵守
