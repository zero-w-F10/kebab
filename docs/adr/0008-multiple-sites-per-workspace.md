# 一个工作区承载多个互不引用的 site

状态：已接受（2026-09-19）

最早按「一个工作区一个站点」设计，内容平铺在仓库根目录。实际使用中需要并排维护多个产品原型（对应 Axure 的多个 `.rp` 文件），且每个都要能独立交付。因此改成 `sites/<id>/` 一原型一目录，各自持有 `site.json`、`pages/`、`assets/`、`prototypes/` 和 `dist/`，互相之间不共享素材也不跨 site 链接；根 `dist/index.html` 只是列出全部 site 的门户页，不参与任何 site 的内容。

## Consequences

- 每个 site 的 `dist/` 自包含，拷走一份就能发给一个人，延续 [ADR-0001](0001-file-protocol-compatible-output.md) 的 `file://` 约束
- 删除或复制一个产品原型等于操作一个目录
- `sites/` 的目录名即 site id，不需要额外维护一份索引
- 公共素材无法复用：两个原型要用同一张图就得各存一份。这是有意为之，换来的是隔离
- 构建按 site 逐个进行，一个失败不会阻止其余的构建；但只要有失败，门户页就不更新，整体退出码为 1

## Considered Options

- **根目录统一一个 `dist/`**——单一出口，但违背「一个原型目录包含它所有内容」，交付时无法按原型切分
- **共享 `assets/` 与 `prototypes/`**——省空间，但一个 site 的改动会波及另一个，删除 site 也变得危险
- **跨 site 的统一导航**——要在每个 site 的导航里注入其他 site 的页面，site 就不再是自包含单元
