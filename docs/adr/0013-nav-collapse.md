# 导航树收起/展开走复选框，状态不跨页保存

状态：已接受（2026-09-21）

导航树占 264px，proto 页的 iframe 与宽的表格都吃这一刀。于是给它加一颗开关：收起后导航缩成 44px 窄轨，里头只留这颗开关，再点一次摊开。

产物里不许有脚本（[ADR-0001](0001-file-protocol-compatible-output.md)），所以开关本身就是一颗复选框：`appearance: none` 自己画成按钮（雪佛龙用两条边框拼一个角，不额外引图标文件），收起靠两条规则 —— `.kebab-nav-toggle:checked ~ .kebab-shell` 在骨架上把自定义属性 `--kebab-nav-width` 改成窄轨宽度，再 `display: none` 掉 `.kebab-brand` 与 `.kebab-tree`。它是**结构**的一部分，复选框必须排在 `.kebab-shell` 前面，挪进 shell 里这两条选择器就不成立了。开关的位置与导航宽度由同一个变量 `--kebab-nav-width` 推出来，收起时只改这一处。

**收起状态不跨页保存**：在导航里点另一页就是换了一份 HTML，复选框回到初始的摊开。这不是疏漏，是无脚本加「每页一个独立文档」的必然结果 —— HTML 里没有地方能存它（fragment 会随链接跳走，cookie 与 localStorage 要脚本）。

## Consequences

- 收起后导航里的字用 `display: none` 藏，不用 `visibility`：看不见的链接不许留在 Tab 顺序里
- 开关 `position: fixed`：长文档滚下去也够得着，且不参与导航内部的排版；正文与它不重叠，proto 页顶部工具条的标题也不受它影响
- 站点标题右边让出 46px，再长的标题也不会钻到开关底下
- 收起的收益在 proto 页的 iframe 与 doc 页正文栏（正文栏跟着窗口走，收起后多出 220px，到 [ADR-0014](0014-doc-column-width.md) 的 1600px 封顶）
- 每换一页都要重新收一次。真要它记住，就得让产物带脚本或起服务器，那正是 ADR-0001 不要的

## Considered Options

- **收起时把导航整个藏掉（宽度 0）** —— 更彻底，但开关只能浮在正文上方；proto 页顶部那条工具条的标题就在左边，一浮上去就压字
- **窄轨里再留一个「概览」图标入口** —— 窄轨不至于空着，但多一个只在收起时才看得见的入口，不值当多讲一条规则
- **`<details open>` 包住导航** —— 同样无脚本，但收起时只剩一个 `summary`，要另做一颗按钮的样子，还得自己处理 flex 宽度，不如复选框直接
- **把状态编进链接（每页 `#nav-rail`）** —— 导航链接是构建期生成的，收起状态是运行期的，两下里碰不上；真让链接带上它，就等于每页的产物都随「上一次点击」而变
