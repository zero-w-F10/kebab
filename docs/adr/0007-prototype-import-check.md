# 原型导入校验

状态：已接受（2026-09-19）

`file://` 约束要求产物能双击运行（见 [ADR-0001](0001-file-protocol-compatible-output.md)），但交付物的主体内容——AI 导出的原型——不在我们控制范围内：它常含 `<script type="module">`（Vite 等打包器的默认产物）、读本地文件的 `fetch()`、公网 CDN 引用，或引用了原型目录里并不存在的资源，在 `file://` 下都会白屏，而原因藏在浏览器控制台里，同事排查不出来。因此原型目录进库前必须扫描这四类问题并拦下。

## Consequences

- 「同事那边白屏」在导入时就被暴露，而不是交付后
- 顺带满足内网离线要求：任何指向公网的东西在这一步被显式列出
- 有误报可能（例如用了 module 但实际无外部依赖），需要强制导入的人工出口
- 扫描要覆盖 HTML 与 JS 文件，且要处理相对路径解析

## Considered Options

- **不校验**——把问题推迟到同事打开时，排查成本高且反馈链长
- **运行时兜底提示**——`file://` 下如果脚本已经挂了，兜底脚本自己也未必能跑起来
