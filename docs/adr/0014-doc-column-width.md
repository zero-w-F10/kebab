# 正文栏跟着窗口走，只留一道 1600px 的护栏

状态：已接受（2026-09-21）

原来正文栏死卡在 880px（去掉内边距 784px）。在一屏 1707px 上，主区有 1443px，正文只用掉 880 —— 右侧挂着一大块空白，正文里的截图还被压到原尺寸的四成，看不清字。

改成跟着窗口走，只留一道 1600px 的上限。1440 / 1707 / 1920 这些常见宽度因此都铺得满（1920 上只差 56px），再宽才由上限接管。上限不是留给「看着整齐」，是留给超宽屏的：一路铺到 3440 的屏上，一行中文会有两百多字，读起来就散了；上限吃满时一行中文约 100 字（1504px 内容 ÷ 15px 字号），这道数字的来由就这一条。

顺带结清两笔旧账：截图不再被压小（1308 宽的图在 1707 的屏上按原尺寸显示，1919 宽的到 78%），以及「收起导航」终于对 doc 页也有意义 —— 以前正文栏卡死，收起导航只便宜了 proto 页的 iframe。

## Consequences

- 表格、代码卡片、图片都跟着变宽；一行正文也随之变长，这是这次明确要的取舍
- 站点概览页用的是同一个 `.kebab-doc`，一并变宽；根门户页是另一套样式，不动
- 收起导航后正文栏再多 220px，到 1600px 封顶（1707 的屏上：摊开铺满，收起只差 63px）
- 正文栏的边距（左右各 48px）不跟着宽度走，它是「纸」的留白，不是比例

## Considered Options

- **只把 880 抬到 1200 上下** —— 1920 的屏上仍剩四百多像素空白，「右边那一大块」只小了一半
- **干脆不设上限** —— 3440 的屏上一行正文铺满 3200px，读不了
- **正文保持窄栏、只让表格与图片破格变宽** —— 阅读体验最好，但右缘参差不齐，同一页里两种宽度来回换，与「把空白用起来」这个诉求也对不上
