# page 递归挂下级，层级不进文件路径

状态：已接受（2026-09-19）

「登录页改版说明」这类页面常要配一条补充说明，两者在导航上是从属关系，平铺成同级说不清谁是谁的补充。因此给 page 加可选的 `children`，形状与 `pages` 之于 module 完全一致、递归下去 —— 同级顺序仍然由数组位置表达（[ADR-0002](0002-manifest-centered-storage.md) 立的那条不动），不新增 `parent` 之类的关系字段，层数也不设上限：限制层级要额外写一条校验和一套解释，而多一层本身不会让任何东西坏掉。关键约束是**层级不进文件路径**：正文位置依然只由 `page id` 推出（`pages/<id>.md`、`prototypes/<id>/`），所以改层级、换父级只在 `site.json` 里挪一行，磁盘上一个文件都不搬。

## Consequences

- 删除必须连带整棵子树：留着下级会变成没有父级的节点
- 拖拽要多一个「变成下级」的落点语义（行高三分：前后＝同级，中间＝下级），并且要拦住把一页拖进它自己的后代
- 导航渲染、doctor 的摊平、清单的校验都改成递归；`site.json` 的缩进会随层级加深
- 前端不做折叠：折叠状态属于界面，存进清单就多一处会互相矛盾的东西

## Considered Options

- **平铺数组 + `parent` 字段** —— 渲染时按 parent 建索引，但同级顺序失去表达（平铺数组里谁挨着谁不再说明问题），要再引入序号字段；而且 `parent` 指向 id，会多出「悬空 parent」这类新的失配要 doctor 兜
- **把补充说明写成 A 正文里的一节（`##`）** —— 不改编任何东西，但那只能是纯文字，挂不了自己的原型；而且不能单独发链接、不能和 A 分开评审
- **把 A 升格成 module** —— module 是功能域一级分组，且自己没有正文；给 A 加正文就等于把两层的语义揉在一起
