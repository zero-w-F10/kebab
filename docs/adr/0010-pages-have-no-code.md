# page 不设展示编号，顺序就是数组位置

状态：已接受（2026-09-19）

[ADR-0005](0005-numbering-scheme.md) 让 page code（`LO-01`）承担「给人引用的稳定把手」，前提是评审时会用编号指代某一页。实际用下来没人这么引，而它的代价是实打实的：建模块要先编一个前缀，清单里多出一个既不参与寻址、也不参与排序的身份字段，而且这个记号长得像位置、干的却是身份的活 —— 一拖顺序，导航树里就出现 `LO-02` 排在 `LO-01` 上面，看着像排序坏了。因此删掉 `code` 与模块上的 `prefix`：page 的身份只剩 `id`（机器把手，决定文件位置，跨页锚点用的就是它），标题是人的把手，顺序由清单里的数组位置表达。ADR-0005 里 section number 那一半继续有效。

## Consequences

- page 可以自由跨 module 搬了：原来「page 不跨 module」的唯一理由是 code 前缀与模块绑定，这条约束随 code 一起消失
- 旧清单里残留的 `code` / `prefix` 不参与构建，编辑器保存一次就顺手剔掉
- doctor 的重复检查只剩 id；标题可以重复，它不是身份
- ADR-0002 说 `site.json` 持有「模块、页面顺序、标题、类型和编号」，其中「编号」一项按本条退役

## Considered Options

- **重排序时重编编号，让编号跟着顺序走** —— 那样编号就成了位置，插一页或删一页会让后面全部平移，SVN diff 炸，已发出去的引用同时失效（ADR-0005 已否决过这条）
- **保留字段，只是不显示** —— 不动数据模型、最容易回退的一版；但它留着「一个没人引用的字段加建模块要编前缀」的摩擦，也没解决「页面上有两个身份」这件事
