# 往 kebab 里加内容

一个产品原型从零到能交付要走的步骤，以及每一步的完成标准。术语见 [CONTEXT.md](../CONTEXT.md)，规则的来由见 [design.md](design.md) 与 [docs/adr/](adr/)。

## 新增一个产品原型

### 1. 建目录

`sites/<site-id>/`。site id 会成为门户页里的标识，用短横线小写英文。

### 2. 写 site.json

```jsonc
{
  "site": { "title": "显示名", "subtitle": "副标题，可选" },
  "modules": [
    {
      "id": "mod-id",
      "title": "模块名",
      "pages": [
        { "id": "page-id", "type": "proto", "title": "页面标题",
          "children": [
            { "id": "page-id-sub", "type": "doc", "title": "它的补充说明" }
          ] }
      ]
    }
  ]
}
```

- `page.id` 同时决定文件位置：proto 页找 `prototypes/<id>/`，doc 页找 `pages/<id>.md`，产物是 `dist/<id>.html`。它是 page 唯一的身份，分配后不要再改
- 数组顺序就是导航顺序：`pages` 里的先后决定页面先后，`modules` 里的先后决定模块先后。想调顺序可以在编辑器里拖，也可以直接改这里的顺序
- `children` 是可选的下级，形状跟 `pages` 一样，可以一直往下套。层级只决定导航树里缩进几级，**不决定文件放哪儿**——下级页的正文照样是 `pages/<id>.md`，所以挪层级不用搬文件
- 树的第一层是 module，module 不能再嵌套

### 3. 放内容

proto 页见下一节，doc 页见下下节。

### 4. 核对

```
npm run doctor
```

**完成标准**：每个 site 都输出 `✓`。`dangling`（清单有、磁盘没有）、`orphan`（磁盘有、清单没有）、`duplicate`（page id 重复）都必须先解决，否则下一步会被拦住。

### 5. 构建

```
npm run build                # 全部 site
npm run build -- <site-id>   # 只构建指定的，可给多个
```

产出 `sites/<id>/dist/`（自包含）和根 `dist/index.html`（门户页）。

编辑器顶部工具栏也有「构建」，构建完能在弹层里直接点开产物预览 —— 改了内容想立刻看交付效果时不用切终端。

### 6. 验证

双击 `sites/<id>/dist/index.html`，逐项确认：

- 地址栏是 `file://`，不是 `http://`
- 左侧导航列出全部页面，且当前页高亮；导航头部那颗开关点一下能把导航收成窄轨，再点一下摊开（换一页会回到摊开，收起状态不跨页保存）
- proto 页的 iframe 里有内容，不是空白
- doc 页的图片正常显示；点一下能放大，按 Esc 或点图周围的空白处能退出

## 加一个 proto 页（AI 导出的页面）

1. 把 AI 导出的**整个目录**放进 `prototypes/<page-id>/`。缺了这一层 page id 目录是最常见的错误。
2. 一个字节都不要改它。
3. 入口默认是 `index.html`；文件名不是这个，就在该 page 里加 `"entry": "实际文件名.html"`。

**导入校验**在构建时拦下四类会让同事白屏的写法：

| 问题 | 为什么 |
|---|---|
| `<script type="module">` | `file://` 下被浏览器按 CORS 规则拦掉 |
| `fetch()` / `XMLHttpRequest` | `file://` 下读不到资源 |
| HTML 的资源属性、CSS 的 `url()` / `@import` 指向公网 | 同事内网离线时加载不到 |
| 同上这些位置引用的本地资源不可用 | 文件没拷全，或路径以 `/` 开头——`file://` 下 `/` 会解析到磁盘根 |

被拦时报告会给每类问题配一句怎么办，出口有三个：

- **首选**：让 AI 重新导出成自包含的单文件版本
- **文件没拷全**：把缺的补进 `prototypes/<page-id>/` 的对应位置
- **确认无碍**：`npm run build -- --force`

`<a href>` 指向公网不算问题，那是点击后才走的链接，不会白屏；JS 里的文档链接和 XML 命名空间也不算，它们只是字符串。校验只报真正会发起请求的位置，所以不存在的本地页面链接（`<a href="xxx.html">`）也不查。

## 加一个 doc 页（截图 + 文字说明）

1. 正文写到 `pages/<page-id>.md`（`pages/` 目录不存在就建）
2. 图片放进 `assets/`
3. 正文里按**站点根**引用图片：写 `assets/shot-1.png`，不是 `../assets/shot-1.png`。源文件和构建产物因此路径一致，不需要重写

**手上已经有写好的 md**：直接丢进 `pages/`，不用先在编辑器里建页再粘贴正文。编辑器两秒内就能看到它，核对角标变红 → 点「核对」→ 面板底部的**全部收编 N 个 md**，一次收编成 doc 页：

- 页面标题默认取正文第一条标题；正文顶格的 `#` 是这一页自己的标题，收编后从正文里抹掉（`##` 是章节，不动）
- 文件名当不了 `page id`（中文名、带点、大小写不对、不叫 `<id>.md`）时，文件会被改名成 `pages/<id>.md`：正文位置由 id 推出，文件名只能跟着它走。收编弹层会把改名清单、id 与标题先列出来
- 不想全收编就用那一行行尾的「⋯」→「收编为页面」，id 与标题都能当场改；「删除文件」是另一个出口

写法约定：

- **正文从 `##` 开始**。`#` 留给页面标题，那个你在 `site.json` 里已经写了
- 标题层级会变成条目编号：`##` → `1`，`###` → `1.1`。渲染时自动算，**不要手写编号** —— 手写了会与自动编号叠在一起（显示成「1 1 调整背景」）
- 每个标题会拿到锚点 `<page-id>-1-2`，可跨页引用：`dist/<page-id>.html#<page-id>-1-2`
- 条目必须是有标题的块。散落的列表项不参与编号，也无法被锚定
- 代码与字段契约用围栏包起来，**并写上语言**：` ```json `、` ```typescript `、` ```sql `、` ```yaml `、` ```bash `（别名如 `ts`、`yml`、`sh` 也认）会在产物里着色，右上角挂语言牌子。**不写语言**就是一张保留空白的朴素卡片 —— ASCII 画的界面草图靠它；写 `text` 则折行（里面通常是人话，别让人横向滚）。`mermaid` 只当纯文本显示，不出图（出图要跑运行时脚本，越了 file:// 的硬约束）
- 图片点开可以看大图：原尺寸居中显示，点图周围的空白处或按 Esc 退出。正文栏跟着窗口走，最宽 1600px（去掉边距 1504px）—— 比这还宽的截图在正文里仍然是被压小的，想看字就点开；小图不会被拉大；整页与手机上的长截图在放大层里上下滚（缩进一屏就比正文里还小）。**包在链接里的图**（`[![说明](assets/a.png)](https://…)`）不参与放大 —— 那一次点击留给跳转

## 用编辑器改内容

导航树和 doc 正文都能在浏览器里改，比手写 `site.json` 稳——编号分配、一致性和陈旧写入都由它兜住。

```
npm run edit -- --site <site-id>      # sites/ 下只有一个产品原型时可以省掉 --site
```

终端会打印一个 `http://127.0.0.1:4173/`，打开它。界面照 axhub make 的习惯排：工作区级的按钮（新建模块、核对、构建、重载、保存）都在顶部工具栏，每个 module 与 page 行尾的「⋯」是它自己的操作菜单。能做的事：

- 新增/删除模块与页面，给页面挂下级，改标题（标题平时是文字，双击就地改）
- 排顺序、调层级都拖每一行行首的「⠿」握把：拖到目标行的上沿 = 跟它同级排在前面，**中间 = 变成它的下级**，下沿 = 跟它同级排在后面；拖到某个 module 的空白处 = 放进那个 module 的根级末尾（也用来把下级提回顶层）。落点会画线或描一圈
- 换 module、换层级、换顺序都只改清单：正文位置由 `page id` 推出，磁盘上一个文件都不搬
- 点开 doc 页直接改正文：块式所见即所得，标题键入 `##` 就是一条（条目编号在构建时才算，这里看的是写作体验）
- 截图直接粘贴或拖进正文，会自动存进 `assets/`，正文里出现的是 `assets/<文件名>`。别手工改成外链或绝对路径
- 正文里不该出现 `data:image/...;base64`。真出现了，保存时会自动把图片搬进 `assets/` 并改掉路径，不用你操心
- proto 页在右侧 iframe 里预览，另有「全屏打开」
- 顶部的「核对」图标带问题条数角标，点开列出悬空引用、孤儿文件、闲置素材、重复 id。往 `pages/` 里丢文件、Agent 在后台改了东西，角标两秒内自己跟上，不用先点重载。孤儿文件的出口在它那一行的「⋯」里：**收编为页面**与**删除文件**；`pages/` 下的 md 还能在面板底部一次全收编
- 删掉正文里的图之后，留在 `assets/` 里的文件会被报成**闲置素材**（这条不拦构建）。点它那一行的「⋯」→「删除文件」清掉即可；删除前会照磁盘当下的正文再核一遍引用，真还有人用着就拒绝

几条约定：

- **保存是手动的**，`Ctrl+S` 同效。保存前会跑一次 doctor，page id 重复会被直接拦下
- `page id` 分配后不要改：它决定文件位置。导航顺序不用手写编号，拖出来的顺序就是顺序
- 新增 proto 页只建目录，把 AI 导出的原型整个放进去，再回编辑器保存
- Agent 在后台改了文件时，编辑器会把状态标成「陈旧」并拦住保存。点「重载」拿到最新内容再继续——这是有意为之，避免覆盖别人的改动

## 常见报错

| 报错 | 原因 | 怎么办 |
|---|---|---|
| `找不到 pages/<id>.md` | 清单里有这个 doc 页，文件没建 | 建文件，或从 `site.json` 删掉这条 |
| `找不到原型入口 prototypes/<id>/index.html` | proto 页缺 page id 那一层目录，或入口文件名不对 | 内容放进 `prototypes/<id>/`；入口不是 `index.html` 就写 `entry` |
| `孤儿文件：pages/xxx.md` | 文件建了，清单里没有 | 在 `site.json` 加一条，或在核对面板里收编它 |
| `孤儿文件：prototypes/xxx` | 同上 | 同上 |
| `闲置素材：assets/xxx` | 图从正文里删掉了，文件还留在磁盘上 | 在核对面板里点它那一行的「⋯」→「删除文件」；只是提示，不影响构建 |
| `page id 只能用小写英文、数字与短横线` | 新建页面时手填的 id 不合规 | 换成合规的；手上已写好的 md 不必改名，走核对面板的「全部收编」，工具自己会改名 |
| `id 重复` | 两处用了同一个 page id | 改掉其中一个。`page id` 分配后本不该变 |
| `引用了 N 个原型目录里没有的文件` | 原型导出时就没带上这些文件，拷贝时又漏了 | 把缺的文件补进 `prototypes/<page-id>/` 的对应位置；补不齐就让 AI 重新导出 |
| `以 / 开头引用本地资源` | 路径写成了站点绝对路径 | 改成相对路径，如 `./assets/logo.png` |
| `sites/ 下没有任何产品原型` | 这个仓库只有工具代码，`sites/` 是你的内容，不在 git 里 | 正常，不是故障。放内容进去即可 |
| `没有这个接口：GET /api/...` | 编辑器服务还是改代码之前启动的那个进程（界面每次刷新，服务端不会） | 重启 `npm run edit -- --site <id>` |
| `指定的产品原型不存在` | `npm run build -- xxx` 的 xxx 写错了 | 报错信息里会列出可用的 id |

## 交付

`sites/<id>/dist/` **完全自包含**：拷走、压缩、丢到任意位置，同事双击 `index.html` 就能看，不需要工具、不需要源码、不需要其他目录。

**不要单独拿走根目录的 `dist/`**。它是门户页，链接写成 `../sites/<id>/dist/index.html`，出了仓库结构就是一堆死链。

构建会删掉并重建 `dist/`，所以要传给 SVN 时，提交前先看一眼哪些是新增（`?`）、哪些已消失（`!`）。
